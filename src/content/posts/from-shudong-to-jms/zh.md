title: '从树洞换到 JMS'
description: '记一次因为 Codex 长时间运行而更换节点订阅的经历。'
pubDate: '2026-10-03T14:04:06+08:00'
---

树洞原来的套餐是每月 25 元、200GB。最近我让 Codex 连着跑计划和任务，经常一跑就是很久，有时白天开始，晚上还在继续。新任务和对话接着来，流量掉得特别快。

我看了下后台，200GB 已经用了 181.18GB，只剩 18.82GB。继续用原来的套餐有点吃紧，我就把预算提到每月 50 到 100 元，想换个流量宽裕些的。美国节点优先，Clash 也想继续用。

我也看过不限流量的 VPN 和自己租服务器这类方案。前者要先确认在我常用的网络上稳不稳，后者还得花时间维护。最后选了 Just My Socks，简称 JMS，买的是 LA 1000：官网当时标价每月 9.88 美元，流量 1TB，大约是原来套餐的五倍。[套餐详情](https://justmysocks.net/members/cart.php)

JMS 有 Mihomo / Clash.Meta 的订阅，导进 Clash Verge 就能用。旧版 Clash 和 ClashX 对部分协议支持不全，购买前可以看一下[兼容说明](https://justmysocks.net/members/index.php?rp=/announcements/34/Clash-support-added.html)。

导入之后，我测了一下实际速度。10 月 3 日下午，通过 Clash 连 Cloudflare 的测速端点，整个过程用了大约 80MB 流量。单连接下载测了三次，另外测了四个连接同时下载和两次上传：

| 测试                 | 结果                     |
| -------------------- | ------------------------ |
| 单连接下载，中位数   | 30.4 Mbps（约 3.8 MB/s） |
| 四连接同时下载，合计 | 147 Mbps（约 18.4 MB/s） |
| 上传，两次平均       | 18.1 Mbps（约 2.3 MB/s） |
| 节点延迟             | 约 100 毫秒              |

单连接三次在 27.5 到 32 Mbps 之间。147 Mbps 是四个连接加在一起的速度，跟单个任务下载时看到的速度不是一回事。平时跑 Codex，后者更接近日常感受。

本次测速自动选中的是 s4，Cloudflare 查到它的出口在日本。套餐名是 LA 1000，实测的这个节点却是日本出口；需要美国出口时，我就手动选确认过的美国节点。

导入时的规则也顺手整理了一下。原来的规则最后只有 `MATCH,JMS`，匹配到的请求都会走 JMS。我加了国内网站、中国 IP 和局域网的直连规则，把 AI 服务单独放进 `AI固定`，其他国外流量放进 `国外上网`，由自动组选节点。配置重载后，我看了下 Clash 的连接记录，路由结果符合预期。

`AI固定` 现在选的是日本 s4，其他国外请求仍然可以用自动组。自动组看延迟挑线路，长时间跑 Codex 时，我更关心任务能不能顺顺当当地跑完；光看延迟数字还不够。

先用一个月再看。Codex 长时间跑下来会用掉多少流量，任务中途会不会掉线，实际跑过才知道；够用再续。
